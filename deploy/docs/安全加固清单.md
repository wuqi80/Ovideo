# Drama 安全加固清单（GCP 防挖矿 / 防接管）

> 2026-06-17｜针对"被扫描→漏洞→植入挖矿→Google 停机"威胁模型的专项安全审计（3 路只读）结论。
> 用户要求：**所有私钥安全、数据库不对外暴露、内网不用弱密码——基本要求必须落实。**

---

## 0. 先说好消息（已核实）
- **git 历史干净**：全部 93 个 commit 未提交过任何真实密钥（含密钥的 `start_cluster.sh`/`local_start.ps1` 从未入库，`.gitignore` 第一次提交前就到位）。→ **无需因"历史泄露"轮换密钥。**
- **无 RCE 命令注入**：所有 ffmpeg/subprocess 调用都用 argv 列表、HTTP 路径上无 `shell=True`；无 eval/exec/pickle/yaml.load。
- 唯一可能需轮换的是 **Gemini key**：若曾在设了 `GEMINI_API_KEY` 的机器上 `npm run build` 并把那批 `dist/` 发到公网，则它会明文烤进前端 JS（本地这份是 `PLACEHOLDER_API_KEY`）。**需核对生产服务器上正在 serve 的 `dist/assets/*.js`**。

## 4. 两条执行线

### A. 部署/运维层（在 GCP 服务器执行 —— 对"防挖矿"最关键，多数无需改代码）
1. **GCP 防火墙只放行 22(限源IP)/80/443**；显式确认 **6379/5432/6006/8188 对 0.0.0.0/0 全部拒绝**。VM 内再加 ufw 兜底。
2. **Redis 设密码**：`/etc/redis/redis.conf` 确认 `bind 127.0.0.1` + `protected-mode yes` + 加 `requirepass <强>`，并设 `REDIS_PASSWORD` 环境变量。
3. **PostgreSQL** 确认 `listen_addresses='localhost'`、pg_hba 不对外；`my2_user` 用强密码（且修复本地 VALID UNTIL/连接问题）。
4. **nginx 强制 HTTPS**（443+证书，80→443 跳转）；给 `/admin`、`/admin-legacy`、`/api/admin`、`/api/agent` 加 IP 白名单/basic auth 做纵深防御。
5. **注入强随机 `JWT_SECRET_KEY`、强 `SUPER_ADMIN_PASSWORD`、强 DB 密码** 到 systemd 环境；改掉 admin 默认口令。
6. 核对线上 `dist/assets/*.js` 是否含真实 Gemini key；若是 → 轮换 Gemini key。

### B. 应用代码层（改仓库代码 —— 不改变正常功能，纵深防御）
1. **C1**：`jwt_auth` 缺 `JWT_SECRET_KEY` 时**拒绝启动**，删硬编码默认常量。
2. **C3**：admin router 挂全局 `Depends(require_admin)`（需先确认 /admin-legacy 控制台带 JWT 调用，避免拆掉后台）。
3. **C2/H5**：移除/禁用硬编码弱口令登录路径，去掉用户名兜底白名单，统一走 DB role + 哈希密码。
4. **H1**：CORS 改显式域名白名单（可配 env）。
5. **H2/H3**：加 `safe_storage_path()` 收敛 + SSRF 防护（禁私网/`169.254.0.0/16`/`127/8`/`::1`/metadata host，仅 https 白名单）。
6. **H4**：开放注册改为默认关闭/邀请码/管理员审批。
7. **H7**：`_encrypt_key` 换 `cryptography.Fernet` 真加密 + 一次性迁移。
8. **H8**：删 geminiService 客户端死代码 + 移除 vite key define（前端不持 key）。
