# Drama 开发规范与目标架构（标准化基线）

> 目的：把现在堆在巨石文件里的逻辑，按标准 MVC 分层梳理——**函数归类、API 归类、层次分开**。
> 本文是后续"阶段3 结构性大拆分"的依据，也是**任何新代码必须遵守的规范**。
> 铁律：**只重组、不改变功能**；**GPU/ComfyUI 为禁改区**（见 §5）。

---

## 0. 现状与差距

| 层 | 现状 | 差距 |
|---|---|---|
| Model（数据） | `dao/` 已按域分包（admin/business/content/creative/organization/user）+ 顶层 shim | ✅ 已达标，**不动** |
| Schema（模型） | Pydantic 请求/响应模型散落在 `cluster_main.py` 里 | ❌ 需归拢到 `schemas/` |
| Service（业务） | `services/` 存在，但大量业务逻辑**内联在路由函数里** | ❌ 需下沉到 service |
| Controller/View（路由） | `cluster_main.py`(6600行,@app) + `api_routes.py` + `admin_routes.py` 混杂 | ❌ 需按域拆成 `routers/` |
| Core（基础设施） | `core/`（db/jwt/worker/queue）、`cluster_config.py` | ✅ 基本就位 |
| Pipeline（GPU） | `pipeline/`（comfyui agent/main/workflow） | 🚫 红线，不动 |

**结论：M 层已达标，要补的是 Schema 归拢 + Service 下沉 + 路由按域拆分。**

## 1. 目标目录结构

```
deploy/
  cluster_main.py      # 瘦身为「应用工厂」：建 app + 中间件 + 注册路由 + lifespan，不含业务
  schemas/             # 所有 Pydantic 模型，按域分文件
      __init__.py
      auth.py  project.py  episode.py  storyboard.py  generation.py  video.py  admin.py ...
  routers/             # 按域拆的 APIRouter（薄控制器：校验入参 → 调 service → 返回）
      __init__.py
      auth.py          # /api/login /api/auth/* /api/user/*
      projects.py      # /api/projects*
      episodes.py      # /api/projects/{}/episodes* /api/episodes/*
      storyboard.py    # /api/episodes/{}/storyboard-items* /api/storyboard-items/*
      generation.py    # /api/generate/*（图像生成业务）
      ai_proxy.py      # /api/deepseek /api/gemini /api/gpt-image /api/doubao（第三方代理）
      video.py         # /api/video/* (crop/合成) /api/episodes/{}/video-segments*
      audio.py         # /api/upload/audio /api/storyboard/mix-audio /audio-tracks*
      media.py         # /api/upload /api/comfyui/upload* /storage 相关
      admin.py         # /api/admin/*（合并 admin_routes）
      agent.py         # /api/agent/*（🚫 红线，保持契约）
      spa.py           # SPA/静态页面路由 + catch-all（永远最后注册）
  services/            # 业务逻辑（路由不写业务，都调这里）
  dao/                 # 数据访问（已达标，不动）
  core/                # db_manager / jwt_auth / worker / task_queue / config
  pipeline/            # 🚫 ComfyUI/GPU 红线
  utils/               # 通用工具（net_guard 等）
```

> 命名：`routers/` 还是 `api/` 二选一即可，本规范用 `routers/`。一个域一个文件，文件名=域名（小写蛇形）。

## 2. 各层职责与规则

### 2.1 Router（控制器层）——**薄**
- 只做三件事：①声明路由 + 依赖鉴权（`Depends`）②校验/解析入参（Pydantic schema）③调用 service、组织响应。
- **禁止**：在路由函数里写 SQL、拼业务逻辑、调第三方 API、操作文件系统。这些一律下沉 service。
- 每个 router 一个 `APIRouter`，在 `cluster_main` 用 `include_router` 注册。

### 2.2 Service（业务层）
- 所有业务逻辑、第三方调用、文件处理、跨 DAO 编排都在这里。
- 纯函数/类，**不依赖 FastAPI 的 Request/Response**（便于测试复用）。入参出参用普通类型或 schema。
- 命名：`services/<域>_service.py`，函数动词开头（`create_x`/`generate_x`/`mix_x`）。

### 2.3 Schema（模型层）
- 所有 `BaseModel`（请求体/响应体）归 `schemas/<域>.py`，禁止再定义在路由文件里。
- 请求模型 `XxxRequest/XxxCreate/XxxUpdate`，响应模型 `XxxResponse/XxxOut`。

### 2.4 DAO（数据层）——已达标
- 只做 SQL/数据访问，不含业务逻辑。已在 `dao/` 分域。保持现状，新表新建对应 dao 模块。
- jsonb 处理统一（待办：连接池注册 codec，见架构审计 §4）。

### 2.5 Core（基础设施）
- db/redis/jwt/worker/queue/config。被各层依赖，不反向依赖业务。

## 3. 路由组织规范（关键）

1. **按域分组**：同一资源的所有端点放同一个 router 文件（"API 归类"）。
2. **统一前缀**：`APIRouter(prefix="/api/projects", tags=["projects"])`。
3. **统一鉴权**：用户端点 `Depends(get_current_user)`；管理端点在 router 上挂 `dependencies=[Depends(require_admin)]`（见安全加固 C3）；agent 端点保持其 token 校验。
4. **注册顺序铁律**：所有业务 router 先 `include_router`，**SPA/静态 catch-all（`/{path:path}`、`/{filename}`）永远最后注册**——否则会吞掉 API 路由（历史踩过坑）。
5. **一个端点只定义一次**：消除当前 `/api/projects/{id}`、双登录等重复/冲突定义（见架构审计 §3）。

## 4. 统一约定

- **认证**：收敛到单一 `core/auth.py`（`get_current_user` / `require_admin`），消除当前 6 套实现。
- **错误**：业务错误抛 `HTTPException`，service 抛领域异常由 router 转换。统一错误响应结构。
- **路径安全**：所有"用户输入→文件路径"必须过 `utils.net_guard.safe_storage_path`；"下载用户 URL"必须过 `assert_public_http_url`（防 SSRF/遍历）。
- **配置/密钥**：只从 env / core.config 读，禁止硬编码（JWT/密码/endpoint）。
- **import**：消费方走顶层 shim 或 `core.`/`services.`/`dao.`；不跨层反向依赖。

## 6. 渐进式迁移计划（合成成片合并后执行）

**不一把梭。逐域搬迁，每步独立可回归、可提交：**

每个域的标准流程：
1. 建 `schemas/<域>.py`，把该域的 Pydantic 模型从 cluster_main 移过去（原处 import）。
2. 建 `routers/<域>.py`，把该域的路由函数从 cluster_main 移过去（逻辑暂原样带走）。
3. 把路由里的业务逻辑下沉到 `services/<域>_service.py`，router 只剩"校验→调service→返回"。
4. cluster_main 用 `include_router` 注册该 router；删除 cluster_main 里的原定义。
5. **冒烟测试该域全部端点**（沿用现有冒烟脚本），确认行为不变 → 提交。

**建议域顺序（从低耦合到高耦合）**：
1. `ai_proxy`（第三方 AI 代理，自包含）→ 2. `video`（ffmpeg）→ 3. `generation`（出图）→
4. `media`（上传）→ 5. `projects`/`episodes`/`storyboard`（CRUD）→ 6. `auth` → 7. `admin`（合并 admin_routes）→
8. 最后 cluster_main 只剩 app 工厂 + lifespan + SPA 注册。

每完成一域提交一次，可随时暂停。预计 8~10 个增量 PR/commit。
