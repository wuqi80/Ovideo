# Drama 架构审计与重构计划（refactor/v2）

> 2026-06-17｜6 路只读审计 agent 全量扫描后的汇总。
> 原则：**不改变任何现有功能**；**本地 GPU/ComfyUI 对接为禁改区**（见 §6 红线）。
> 战略背景：后续要把所有外部 API 换成自建 → provider 层可插拔化是核心目标。

## 0. 一页纸结论

| 维度 | 现状 | 最大问题 |
|---|---|---|
| 后端体量 | cluster_main.py 6596 + api_routes.py 3266 + admin_routes.py 1758 行 | 巨石文件，8+ 职责混杂 |
| 路由 | @app 与 APIRouter 混用，靠注册顺序决定"谁生效" | **项目接口双模型并存**、双登录、死代码路由 |

## 1. 紧急/部署阻塞类（必须最先修）

### 1.1 全新空库建不出来（部署拦路石）— 高
- `database_schema.sql` 只建 10 张基础表；功能表全在 28 个 `db_migration_*.sql` 里。
- **FK/ALTER 顺序错**（按字母序自动跑会硬失败）：
  - `db_migration_assets.sql:10`、`db_migration_audio_tracks.sql:9` 引用 `episodes`，但 episodes 在 `episodes.sql`（字母序更靠后）。
  - `db_migration_admin_extra.sql:29-42` ALTER `credit_accounts/credit_transactions/media_library_items`，但这些表在 credits.sql/media_library.sql（更靠后）。`IF NOT EXISTS` 只保列不保表。
  - `script_id.sql`/`storyboard_audio_mix.sql` ALTER `storyboard_items`，早于 `storyboard_items.sql`。
- 部署脚本三者不一：`scripts/deploy_database.sh:69` / `db_tool.py:316` **只跑 schema、完全不跑迁移**；`auto_deploy.sh:47-58` 只手列 12/28 且路径写成不存在的 `sql/` 子目录 → `|| true` 静默跳过。
- **修法**：建一个显式有序的建库 runner（依赖序：先 episodes/credits/media_library/storyboard_items/canvas_boards，再 ALTER 它们的迁移），或给迁移加数字前缀。纯运维脚本调整，不动应用代码。**修完同步更正《GCP 上线清单》§3。**

### 1.2 无鉴权信息泄露 — 高
- `api_routes.py:182 GET /api/debug/file/{file_id}`：**无鉴权**，回显绝对路径、cwd、父目录文件列表。
- `api_routes.py:167 GET /api/debug/auth-status`：无鉴权回显 token 解析结果。
- **修法**：删除，或至少加 `require_admin`。

### 1.3 任务永久卡死 / 静默丢弃 — 高
- **无 stale-reaper 定时任务**：`TaskDAO.cleanup_stale()` 只能手工触发（`admin_routes.py:939`），没有后台循环调它（对比 agent_stale_checker 是有定时的）。worker 崩溃或无 GPU agent 的任务永远停在 pending/processing。
- **api_call 任务静默丢弃（R5）**：`api_router.py:87-89` 的 api_call 任务绕过 enqueue（不写 hash），若被 lite worker 的 `dequeue` 先 pop 到，`get_task` 返回 None → 任务凭空消失。
- **修法**：① 仿 agent_stale_checker 加一个 stale-reaper 循环周期调 cleanup_stale；② `dequeue` 遇到 JSON-dict member（api_call 格式）原样放回队列让 agent 取。**均不碰 agent HTTP 契约。**

## 2. API 厂商层 → 可插拔抽象（战略核心：为"换自建 API"铺路）

### 现状
- **无统一 provider 接口**（仅 `services/audio_provider.py` 有 ABC+factory，是唯一范本）。
- 视频：`external_api/video/{minimax,seedance,sora2,veo,wan2,dashscope}.py` 各写各的，`wait_for_completion`/`download_video`/`__init__`/单例工厂**逐字复制 4~6 份**；wan2 与 dashscope **同一家（DashScope）实现了两遍**。
- 文本/图像：`gemini_text_chat`/`gemini_image_generate`/`gpt_image_generate`/`doubao` 是 `cluster_main.py` 里的**内联 @app 路由 + 模块全局变量**，根本不是类，无法替换实现。
- **DB `api_configurations.endpoint` 列是死配置**：`load_api_configs_to_env` 把它写进 `*_ENDPOINT` 环境变量，但**全仓库无代码读取**；所有 base_url 硬编码。→ 后台改 endpoint 完全无效。
- laozhang 网关 `https://api.laozhang.ai` **硬编码 6 处**。
- 选择逻辑是 `core/worker.py:298-319` 的 `if/elif task_type` 字符串前缀匹配，不是注册表。
- **`api_router.py` 的 `SmartApiRouter` 是现成但从未被调用的死代码**——它已实现 DB 驱动的 direct/agent/custom 三种调用模式，可作为抽象层骨架。

### 目标结构（不改功能，纯收敛）
1. **`ProviderConfig` 解析器**（新）：单一入口 `resolve(provider_key) -> {api_key, base_url, model, headers, timeout}`，优先级显式 DB→env→默认常量。让 DB endpoint 列**变活**，laozhang 收敛成一处默认。【低】
2. **`BaseVideoClient`**（新基类）：上提 `wait_for_completion`/`download_video`/`__init__`/工厂；子类只声明 `BASE_URL`/`_submit_payload`/`_parse_status`/`_extract_video_url`。先把 wan2 并进 dashscope 做试点（零行为差异）。【中】
3. **`ProviderRegistry`**（新）：`task_type/model → provider class` 注册表，取代 worker 的 if/elif。【中，碰 worker 需回归全部视频 task_type】
4. **文本/图像 client 化**：把 4 个内联路由抽成 `TextProvider/ImageProvider` 子类，响应解析分 `OpenAIChatAdapter/GeminiAdapter`，自建 API 接其一即可。【中高，碰 cluster_main 巨石 + SSE 流式路径】

落地后："换自建 API" = 注册表加一行 + 写一个 adapter + 后台 DB 配置 endpoint/key。

## 3. 路由 / 认证收口

### 路由冲突（按危险度）
| 路径 | A | B | 生效 | 风险 |
|---|---|---|---|---|
| `GET /api/projects/{id}` | cluster_main.py:4241（settings-JSON 模型） | api_routes.py:433（ProjectDAO+版本模型） | A | **高：双数据模型，靠注册顺序，最大地雷** |
| `POST /api/login`(JWT) vs `POST /api/auth/login`(返回裸 user_id) | cluster_main.py:1161 | api_routes.py:264 | 都可调 | 高：auth_login 的 token 过不了下游 JWT，半坏死 |
| `GET /api/admin/users` 等 | admin_routes.py:1080（角色制） | cluster_main.py:5594（硬编码 allowlist） | admin_routes | 中：cluster_main 版是被遮蔽死代码 |

### 认证（6 套实现 → 收敛为 1）
`require_auth`/`verify_session`(cluster_main) · `get_current_user`(api_routes) · `require_admin`(admin_routes) · `_current_user`(share_routes 自写 JWT) · `_verify_agent_token`(agent，**属禁改区**) · 硬编码 allowlist(cluster_main 死代码)。
- **修法**：抽 `auth.py` 公共模块，把用户鉴权三处 JWT 解析合一；admin 统一走 require_admin；agent token 不动。【中】
- `require_auth` 里"自动建库用户"副作用（cluster_main:816-840）拆成独立调用。

## 4. 数据层

- **jsonb 处理 16 处不一致**：`core/db_manager.py:38` 连接池未注册 jsonb codec → asyncpg 返回 str，各 DAO 自行 loads（16 个只写不解码 / 4 个复制 `_coerce_jsonb` / 2 个内联判断）。**修法**：连接池 `init` 注册 `set_type_codec('jsonb', json.dumps, json.loads)` 一次性统一。【中，jsonb 触点多需回归】
- **死代码**：`dao_task_history.py` shim + `dao/business/task_history.py`（0 引用，功能已并入 task.py）；`DatabaseManager.transaction()`(db_manager.py:91) 写法错误且 0 调用。可删。【低】
- **路由越界写 SQL**：`api_routes.py` 18 处裸 SQL（尤其 1826-1869 手写事务）。逐步收口到 DAO。【中】
- 59 个 shim 中仅 `dao_task_history` 是死垫片；其余在用，**保留**（批量改直接 import 收益低、改动 70+ 行，不做）。

## 5. 前端

- ✅ 业务 API 已基本收口 `apiService.ts`，AI 全走后端 proxy（换后端理论只改 `API_BASE` + nginx）。
- **getHeaders/Authorization 重复 24+ 处**（videoService 自带第二个 `API_BASE`；geminiService 24 处内联）。**换 API 前必须先做 `httpClient` 收口**，否则换鉴权=改 24 个文件。【中】
- **geminiService.ts 客户端直连 Google 是死代码**（6 个文本函数零 UI 引用），但 `vite.config.ts:23-26` 把 `GEMINI_API_KEY` **打进了前端 bundle**（密钥泄漏）。删死代码 + 移除 define + 删 `@google/genai` 依赖。【低，已确认零引用】
- **两代页面并存**：`pages/{Generation,VideoGen,Materials,History}Page` vs `components/{Generation,Video,Material,History}Page`，同名 `GenerationPage` 在两目录两路由都活着。需明确归属。【高】
- `WorkspaceApp.tsx`(117KB) 自管第三套 files/storyboard state + 双通知系统，遗留反模式，逐步退役。【高】
- 超大组件：VideoPage 4014 / GenerationPage 3879 / MaterialPage 2260 / AdminPage 2011 行，可按区拆分。
- 重复：媒体加 token helper 3 份、snake→camel normalize 多处、模型档位硬编码多处。

## 6. 🚫 禁改区红线（本地 GPU/ComfyUI，绝对不动语义）

**文件级冻结**：
- `pipeline/comfyui_agent.py`、`pipeline/comfyui_main.py`（远程 GPU 进程 + 单机直连）
- `agent_routes.py` 全文（/register /heartbeat /poll /complete 的请求/响应 schema）
- `dao/admin/agent.py`（AgentDAO）
- `services/task_service.py` 的 `_prepare_for_agent`、`pipeline/workflow_handler.py`、`pipeline/workflow_config.py`、`workflows/*.json`
- `core/task_queue.py` 的 Redis key 契约、`core/worker.py:47-68` 的 `is_external_api_task` 与 lite 守卫
- `cluster_config.py` 的 `RedisConfig`/`SystemConfig`(AGENT_ONLY_MODE) 常量
- 前端 `GenerationPage.tsx` 的 `COMFYUI_MODELS` 集合、`taskRegistry` STALE 保护、`/api/video/capabilities` 探测

**冻结的交界接口**（重构其他部分时签名/字段不可变）：
1. 4 个 agent HTTP 端点的 body/form/返回结构
2. Redis key：`comfyui:task_queue`、`comfyui:task:{id}` hash 字段、`task_complete:{user_id}` 频道、score 公式
3. task_data 约定字段：`workflow_json`、`agent_files`
4. `workflow_handler.build_workflow_for_task` 签名 + 占位符语法
5. `WORKFLOW_CONFIGS` 档位 key 字符串（前端硬编码）
6. AgentDAO 查询接口
7. **新增外部 API 模型时，必须先更新 `core/worker.py` 的 `EXTERNAL_API_TASK_TYPES_EXACT/_PREFIXES`**，否则该任务会被 lite worker 当 ComfyUI 任务丢给不存在的 agent（最隐蔽的耦合雷）

**演进方式**：只加新字段/新端点，不改/删旧的；触碰交界前先用真实 `comfyui_agent.py` 跑一遍 register→poll→complete 回归。
