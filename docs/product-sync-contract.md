# Ostory TV / SPTI 产品与代码库边界契约

## 1. 产品、代码库与发布边界

- `wuqi80/Ovideo:main`：Ostory TV 的唯一开发主线，发布到 `https://tv.ostory.ai`。
- `wuqi80/Ovideo:archive/ovideo-main-20260820`：仓库切代前的 Ovideo 历史归档，只读保留，不再作为开发或部署来源。
- `wuqi80/Drama:refactor/v2`：SPTI 的独立开发主线，发布到 `https://spti.ai`。
- `wuqi80/Drama:NewUI`：仅作为本次迁移来源；切代后不再承担 Ostory TV 开发。

Ostory TV 与 SPTI 不再采用分支前向合并模式。两个仓库分别维护需求、版本、配置、数据和发布历史；任何跨产品能力都必须作为一次显式移植单独评审、测试和发布，禁止自动镜像整个分支或数据库。

## 2. 跨产品能力移植规则

1. 先明确能力属于 Ostory TV、SPTI，还是两者都需要；不得因为实现相似就默认同步。
2. 需要移植时只迁移经过评审的提交或补丁，不合并对方完整主线。
3. 数据库迁移、账务、任务状态、权限、模型绑定和 GPU Agent 变更必须分别评估现有数据与部署环境。
4. 测试在目标仓库独立运行；源产品测试通过不能替代目标产品验收。
5. 品牌、导航、默认值、API 厂商配置、用户数据、密钥和发布元数据始终隔离。
6. API 厂商配置只允许通过受控导出、目标备份、dry-run 和重新加密导入流程迁移，禁止复制整库。

### Ostory TV 的简洁体验

- 默认入口只要求一句话创意；题材、时长、模型等参数按需展开，系统提供可修改的默认值。
- 面向用户的主流程统一表达为“写故事 → 定角色和场景 → 排画面和声音 → 生成短片”，专业术语只在对应编辑器内出现。
- 高级画布、素材和版本记录放入“更多功能”，不阻塞第一次创作。
- AI 生成前必须让用户看到输入和预计点数，并由用户主动确认；不得为了“一键化”静默生成或扣点。
- `/create` 的一句话创意必须绑定到新建分集并持久化，进入剧本页后可继续修改，不依赖易丢失的临时页面状态。

## 3. Ostory TV 核心产品原则

| 产品原则 | Ostory TV 当前承载 | 状态与约束 |
|---|---|---|
| 一切产物是资产并保留血缘 | `files`、`entity_files`、`task_files`、素材库与任务记录 | 已有主体能力。新增产物必须记录来源实体、任务、模型与参数；付费产物不得因上游修改自动删除。 |
| 项目级标签、镜头级绑定 | 项目资产、分镜 `bound_assets`、角色/场景/道具数据 | 部分具备。后续应统一为“项目默认绑定 + 镜头覆盖”，生成执行时读取最新绑定。 |
| 上游变化只标记下游失效 | 当前有任务超时清理和剧本版本回退，但缺少内容血缘级 stale 传播 | 能力缺口。上线版本不得用任务超时状态冒充内容失效；需单独设计迁移、溯源事件和批量处理 UI。 |
| 多次生成形成 Takes，只有一个 selected | 生图 `selectedImageId`、视频片段/版本、任务历史 | 部分具备。API 应逐步统一为保留全部候选、显式选择、可回切，禁止选择动作删除旧产物。 |
| 时长事实自配音向视频和剪辑传递 | 音频轨、视频片段、时间线与合成服务 | 已有主体能力。所有新流程必须复用同一时长事实源，不新增页面私有副本。 |
| 对话生成内容，结构化 UI 负责确认 | 剧本对话、版本、分段与工作流页面 | 部分具备。重要结构变更应先形成差异预览，再由用户确认落库。 |
| 所有生成进入统一任务状态机 | PostgreSQL 任务、Redis 队列、Worker、GPU Agent、通知 | 继续以本仓库状态机、重试、积分冻结/结算为唯一实现。 |
| 模型能力描述驱动 UI 与调度 | API 配置、模型绑定、健康检查、视频能力服务 | 已具备。禁止在页面新增绕过后台配置的模型硬编码。 |
| 长镜头分段、首尾衔接与声音一致性 | 视频分段/合并、H3 运行时、角色声音与音频工作台 | 已有主体能力。选择上游片段后，下游衔接与合成必须可追溯、可重算。 |

## 4. 增量落地顺序

### P0：每次 Ostory TV 开发都必须遵守

- 付费产物不自动删除、不静默重生成。
- 任务实际执行模型、计费规则、输入文件和输出文件必须可追溯。
- 模型能力、健康状态和计费从后台配置读取。
- 跨产品能力必须在目标仓库独立评审和验证，不再自动同步 `Drama/refactor/v2`。

### P1：下一阶段共享领域能力

- 统一图片、视频、音频候选的 Take/selected API 语义。
- 建立项目默认绑定与镜头覆盖的实时解析服务。
- 建立内容级 stale 事件、影响范围预览、忽略和批量重生成流程。

### P2：创作体验深化

- 剧本/分镜结构化 patch 与镜头级差异预览。
- 统一时长事实源和模型时长上限驱动的分段建议。
- 资产血缘视图、成片用料清单与历史 Take 回切。

## 5. 发布门禁

发布 Ostory TV 前必须确认：

- 共享迁移清单完整且可重复执行；
- 路由契约、积分与任务状态测试通过；
- Ostory TV 设计契约、导航与生产构建通过；
- 没有未解释的回归、冲突标记或未提交文件；
- 部署环境的域名、CORS、集群 URL、GPU Agent URL 和 HTTPS 配置一致；
- 发布来源必须是 `wuqi80/Ovideo:main`，目标只能是 `tv.ostory.ai`。
