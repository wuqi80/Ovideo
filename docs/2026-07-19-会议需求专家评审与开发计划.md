评审原则：先确认真实产品决策，再核对当前实现；已有能力以回归测试为主，缺失能力才进入开发；涉及权限、计费、异步任务和数据迁移的事项不采用页面级临时补丁。

## 2. 专家结论

### 2.1 可以直接进入本轮开发

| 需求 | 代码核对 | 结论 |
|---|---|---|
| 人物和道具标准参考图 | 人物已有部分四视图逻辑，道具未强制白底四视图 | 本批补齐统一规则 |
| 剧本二次对话修改 | 只有一键改写和选区润色，没有完整剧本的多轮候选稿 | 本批新增“候选、继续修改、确认应用” |
| 分镜参考素材实际传递 | 当前已自动解析人物/场景/道具绑定、限制六图并保存请求快照 | 不重写，纳入专项回归 |
| 分镜九宫格和全景工具 | 当前 `StoryboardToolModal` 已有入口 | 不重写，纳入专项回归 |
| 视频抽帧、切片和相邻合并 | 当前视频页已有入口和操作链路 | 不重写，纳入专项回归 |
| GPU 角度调整和高清放大节点选择 | 当前设计页、素材页已有 `GpuNodeSelector` | 不重写，纳入双节点回归 |
| 视频反推进入标准流程 | 任务结果只能查看和复制，未绑定分集，也不能形成剧本文件 | 本批补齐候选剧本闭环 |

### 2.2 需要按架构任务实施

| 需求 | 风险 | 建议实施方式 |
|---|---|---|
| 所有模型调用统一积分 | 简单“调用前扣分”会造成重复扣费、失败不退和供应商已执行但本地无账 | 建立 `estimate -> freeze -> enqueue -> confirm/release` 统一提交器，加入幂等键和调用账本 |
| 候选分镜版本和采用命令 | 直接重生成会混入活动镜头，影响视频和成品 | 增加分镜修订实体、差异预览和显式采用命令 |
| 异步任务恢复 | 多状态源会导致刷新后 0%、永久运行或重复付费 | 数据库作为终态事实源，持久化供应商任务 ID、心跳、状态版本和重试策略 |
| 私有媒体签名访问 | 直接关闭 `/storage`、`/uploads` 会让历史素材整体失效 | 先上线签名 URL 兼容层和调用点监控，再关闭裸路径 |
| 规范化素材绑定 | 名称和提示词匹配无法作为长期事实来源 | 增加稳定资产/文件版本绑定表，迁移期双写并保存每次请求快照 |

### 2.3 暂不按会议示例直接开发

- **删除全部排队体系**：会议确认的是弃用旧集群/SSH 路径，自建 GPU2 仍需要任务状态、取消、恢复和并发保护。
- **积分直接减余额**：不满足并发、退款、幂等和对账要求。
- **二创工作流**：方向成立，但换角、多人替换、内容安全、素材权属和计费合同尚未冻结，应先做技术验证和产品原型。
- **分享与评论闭环**：需要先确定外部访问权限、版本引用、评论定位和通知规则，再进入正式开发。
- **模型自动上下架**：供应商元数据不统一，先做后台显式状态和健康检测，不静默改变线上路由。

## 3. 本批实现

### 3.1 人物/道具标准四视图

- 人物和道具默认启用标准四视图，场景不受影响。
- 道具强制同一物体的前、后、左、右视图。
- 锁定形状、比例、材质、颜色、磨损和装饰细节。
- 强制纯白背景，禁止人物、手、场景、文字、边框和额外物体。
- 标准四视图统一使用 `16:9`，单次生成和批量生成共享同一规则。

### 3.2 剧本 AI 对话修改

- 在文字脚本栏增加独立的“AI 对话修改”入口。
- 每轮基于当前候选稿继续修改，并携带最近的修改意见。
- AI 必须返回完整剧本，不允许只返回差异或省略未修改部分。
- 候选稿不会自动覆盖文件；用户点击“应用到当前文件”后才写回。
- 写回复用现有文件历史、撤销/重做和持久化链路。
- 切换文件会重置面板，避免把候选稿应用到错误剧本。

### 3.3 视频反推候选剧本

- 分集页面创建的视频反推任务写入 `episode_id`，历史任务按项目和分集隔离。
- 已完成的反推任务可直接创建当前分集的候选剧本，保留来源任务、视频、时长、积分和完成时间。
- 候选正文按整体内容和时间顺序组织镜头、画面、镜头语言、运动及生成提示词。
- 同一反推任务重复操作时打开已有候选，不重复创建文件。
- 新候选只作为当前浏览文件打开，不自动设为本集采用剧本；后续流程仍以用户明确选择的主剧本为准。

## 4. 后续实施批次

### 批次 A：主流程数据闭环

1. 候选分镜修订、差异预览、显式采用和历史恢复。
2. 外部参考素材统一入库，完成规范化资产绑定表和迁移双写。
3. 视频工作区 take 版本、选定 take 和成品引用一致性回归。

### 批次 B：付费和长任务可靠性

1. 图片、视频、语音、GPU、反推统一积分提交器。
2. 供应商调用账本、Key 指纹、套餐、参数、任务 ID 和产物关联。
3. 统一任务状态机、心跳、断点恢复、取消和未知状态处理。
4. 失败、取消、重启和重复请求下的积分守恒压力测试。

### 批次 C：媒体安全与发布

1. 短时签名 URL 兼容层和 Range 播放。
2. 关闭匿名静态媒体路径前的调用点迁移与监控。
3. 成品发布版本、镜头 take、音轨模式和编辑版本快照。
4. 分享、评论和二创在权限及版本模型冻结后进入开发。

## 5. 本批验收标准

1. 人物或道具单次、批量生成均可关闭/启用标准四视图；开启后请求比例为 `16:9`。
2. 道具提示词明确要求白底、同一物体四视角且无人物、手和场景。
3. 场景生成提示词和比例不受四视图规则影响。
4. AI 对话第一轮以当前文件正文为基线，第二轮以第一轮候选稿为基线。
5. 未点击应用时，当前文件正文不得改变。
6. 应用候选稿后可通过现有撤销功能恢复。
7. 分集视频反推历史不得混入同项目其他分集任务。
8. 已完成的反推结果可创建候选剧本；重复点击不生成重复文件。
9. 打开反推候选时不得改变本集采用剧本。
10. 新增单元测试通过，前端生产构建成功。
