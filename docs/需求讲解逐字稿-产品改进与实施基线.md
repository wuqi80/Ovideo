# 功能讲解逐字稿：产品改进与实施基线

## 1. 文档目的

本文件把《需求讲解视频-转写稿》中的口头问题转化为可设计、可开发、可测试、可上线验收的需求基线。后续修改以本文件的需求编号为准，不再以单个页面截图或临时补丁作为最终产品规则。

评审角色包括：

- 产品负责人：梳理一集单链路、候选方案与当前采用结果。
- 交互设计：梳理主任务、危险操作、反馈、任务中心和后台配置体验。
- 架构与数据：梳理项目、分集、剧本、分镜、素材、任务的归属和迁移。
- AI 与多媒体：梳理模型能力、参考素材、参数、降级、轮询和质量验收。
- 质量与安全：梳理对象权限、积分、幂等、任务恢复、部署和回归门槛。

## 2. 产品总原则

1. **一集只有一条活动生产链路。**一集允许保存多个候选剧本和多个生成版本，但只有一个主剧本、一个当前采用分镜版本、一套活动时间轴进入后续流程。
2. **候选与采用必须分开。**生成结果默认是候选；只有用户明确采用后，才替换当前链路。历史图片、音频、视频和成品保留，不自动删除。
3. **显式绑定是唯一事实来源。**角色、场景、道具必须通过稳定资产 ID 和文件版本绑定；名称和提示词匹配只能做推荐，不能静默生效。
4. **模型真实能力必须可见。**前台参数来自模型能力配置，不允许静默修改分辨率、时长、输入类型或计费通道。
5. **数据库是异步任务最终事实源。**Redis、SSE、本地缓存只用于加速，不得覆盖数据库终态，也不得把未知进度显示为 0%。
6. **昂贵操作必须可追踪、可取消、可对账。**模型、Key 指纹、套餐、参数、供应商任务 ID、积分变化和产物必须形成同一调用账本。
7. **危险操作必须可预览、可恢复。**覆盖导入、切换活动版本、删除时间轴或素材前显示差异并创建恢复点。

## 3. 目标业务链路

```text
项目（默认私有，显式成员）
  -> 分集
     -> 候选剧本 A / B / C
        -> 用户设定主剧本
        -> 生成候选分镜版本
        -> 用户采用一个分镜版本
     -> 设计与素材（本集累计资产，带来源）
        -> 分镜资产绑定快照
        -> 图片生成与质量验收
     -> 参考配音与镜头时长
     -> 视频工作区（差异同步、多个 take、选定 take）
     -> 美化与时间轴（音轨、对嘴、GPU 工具）
     -> 成品版本（明确发布）
```

## 4. P0：必须优先解决

### SEC-001 项目及创作对象权限闭环

**问题**：当前项目已有成员模型，但分集、剧本、分镜、任务、文件和视频反推等接口仍存在只校验登录、不校验项目成员的路径。

**要求**：

- 新项目默认私有；创建时可按用户名添加成员。
- 每个分集、剧本、分镜、素材、文件、任务请求都必须通过所属项目检查访问者角色。
- 非成员访问返回统一 404 或不泄露对象存在性的 403。
- 移除成员不删除其已产生的内容，后续操作记录当前操作者。
- 任务状态、取消、删除必须先校验所有权，再读取结果或删除物理文件。

**验收**：用户 B 获取用户 A 的资源 ID 后，所有读取、更新、取消和删除接口均失败，且不泄露内容、状态或文件路径。

**当前状态**：第一阶段完成，对象级路由静态审计与专项收口已完成。项目创建默认私有和创建时指定成员已实现；已建立统一项目访问服务与实体访问服务，并覆盖分集、分镜、脚本时间轴、素材、视频、音色参考、媒体库、视频反推、任务、实体文件、旧版 Range 下载、Canvas、视频裁剪、通用上传版本、缩略图、ComfyUI 文件代理、MiniMax 共享账户对象、全部图像/素材生成请求范围以及独立旧 ComfyUI 服务。剩余安全主项为 SEC-002 签名 URL 兼容迁移与关闭裸静态路径。

### SEC-002 私有媒体交付与签名 URL

**问题**：`/storage`、`/uploads` 当前直接静态挂载，知道 URL 即可匿名读取；旧文件下载接口的 token 校验发现非所有者时只记录日志，不拒绝访问。

**要求**：

- 私有媒体统一通过短时签名 URL 或认证下载路由交付，签名绑定文件 ID、访问者、过期时间和可选 Range 范围。
- 下载前解析文件所属项目并执行 `require_file_access`；失败统一返回 404。
- 浏览器图片、音频、视频和 GPU 节点下载统一使用同一签名 URL 服务，不依赖永久查询 token。
- `/storage`、`/uploads` 取消公网静态挂载；迁移期至少禁止公共缓存，并记录仍在使用裸路径的调用点。

**验收**：未登录、非项目成员、过期签名和篡改签名均无法读取媒体；合法成员可正常使用图片、音视频 Range 播放和 GPU 拉取。

**当前状态**：设计与静态审计完成，待先上线签名 URL 兼容层，再关闭裸静态路径；不得直接移除挂载导致现有素材整体失效。

### FLOW-001 一集单链路和当前采用版本

**问题**：多剧本候选、按剧本隔离分镜和按分集聚合素材并存；分镜重生成会无标识追加，成品可能混入非主剧本镜头。

**要求**：

- `episode` 明确保存 `active_script_id` 和 `active_storyboard_revision_id`。
- 浏览某个剧本不等于设为主剧本；设为主剧本是独立命令。
- 每个候选剧本独立保存文字、视频脚本和候选分镜。
- 重生成产生候选分镜版本，接受前不影响当前活动链路。
- 接受新版本后，旧镜头标记归档；旧素材和生成结果仍可在历史中访问。
- 视频导入、成品挑选和合成只读取当前采用分镜版本。

**验收**：同一剧本连续生成两次，不会在镜头 11 后追加重复镜头；切换候选浏览不会改变视频和成品；只有“采用此分镜版本”会改变后续活动链路。

**当前状态**：第一阶段完成。当前主剧本的批量分镜写入改为事务内替换，按镜头标识匹配并保留已有文件、音频、视频关联；不再把同一次重生成无标识追加到末尾。完整的候选分镜修订与“采用版本”命令仍待实现。

### ASSET-001 规范化素材绑定与请求快照

**问题**：绑定使用 `char:name`、`sel:name:materialId` 等字符串；缺失时通过名称、提示词或第一张图片兜底，界面显示绑定并不等于供应商请求实际使用。

**要求**：

- 新增规范绑定记录：`storyboard_item_id + asset_id + entity_file_id + role + locked + binding_version`。
- 角色、场景、道具的明确绑定必须优先于手工补充图。
- 没有绑定时只给推荐，不自动写入；关键角色或场景缺失时阻止批量生成。
- 每次生成保存请求快照：资产 ID、文件 ID、图片 URL、参考职责、上传顺序、模型能力上限。
- 外部上传参考图进入统一资产库，镜头保存资产引用而非孤立副本。
- 迁移阶段双写旧字符串和新绑定表，确认所有生成入口切换后再停读旧字段。

**验收**：从任意生成结果可追溯“用了哪些角色、场景、道具图片”；锁定参考不可被名称匹配或默认图片替换。

**当前状态**：第二步已完成。分镜页显示实际提交数量和未提交素材；关键角色/场景因六图上限被排除时阻止生成。Gemini、GPT 图像和豆包请求现在保存实际提交的参考素材快照，包含顺序、资产 ID、文件 ID、职责、锁定状态和内容指纹；分镜的 `configured_references` 已贯通数据库、DAO、同步/替换接口与新旧前端，刷新和匹配镜头重生成不再丢失。规范绑定表和外部参考入库仍待实现。

### TASK-001 统一异步任务状态机与恢复

**问题**：任务状态同时存在数据库、Redis、SSE、本地恢复器和注册表；前端降级轮询会把活动任务写成 0%，长任务可能消失或永久运行。

**要求**：

- 统一状态：`preflight -> submitted -> provider_accepted -> processing -> artifact_validating -> quality_review -> completed/failed/cancelled/unknown`。
- `tasks` 增加业务归属、`provider_task_id`、进度、状态版本、心跳、幂等键和下一次重试时间。
- 供应商受理后立即持久化供应商任务 ID；服务重启后继续追踪原任务。
- 网络、429、5xx 指数退避；鉴权、余额、模型未开通和参数非法不自动重试。
- 超时任务标记“状态待确认”，不得直接重复扣费提交。
- 前端展示最后心跳、可能卡住、可展开错误、Request ID、重试和取消。

**验收**：运行超过一小时并刷新、断开 SSE、重启 API/worker 后，任务在 60 秒内恢复到真实状态；进度不得回退到 0%。

**当前状态**：第一阶段完成。任务列表合并 Redis 实时状态与 PostgreSQL 历史记录，Redis 存在时覆盖旧状态；未知进度保持为空，不再伪造 0%；前端统一将后端 0-100 百分比归一化为 0-1。完整状态机、供应商任务恢复和心跳字段仍待实施。

### CREDIT-001 积分和付费任务原子闭环

**问题**：积分冻结主要覆盖视频反推；任务可能先入队后冻结，冻结失败时供应商仍执行；同一任务可能产生多条活动冻结。

**要求**：

- 所有图片、视频、语音、GPU 和反推任务统一经过 `estimate -> freeze -> enqueue -> confirm/release`。
- 业务请求携带幂等键；同一请求只能创建一个任务、一次供应商调用和一条活动冻结。
- 每个任务最多一条活动冻结，数据库增加部分唯一约束。
- 取消业务任务必须同时取消底层任务和供应商任务，再按最终状态结算或释放。
- 新用户赠送以 `signup_grant` 流水幂等，不以“是否已有零分账户”判断。

**验收**：20 个并发重复请求最终只有一次费用；任何失败、取消和重启场景下 `可用 + 冻结 + 已消费`守恒。

**当前状态**：视频反推链路第一阶段完成。冻结前置到入队之前，提交失败释放冻结，取消先取消底层任务再退款；同一 `task_id` 的冻结使用事务锁保证幂等，新用户开户和历史补发以 `signup_grant` 流水判定。图片、视频、语音和 GPU 的统一付费提交器仍待扩展。

### DEPLOY-001 可审计迁移和上线阻断

**问题**：常用部署脚本未执行完整迁移，部分迁移错误被忽略，导致线上代码和表结构不一致并出现“修改被回滚”的表象。

**要求**：

- 建立 migration ledger，所有迁移有唯一版本、校验和、执行状态和时间。
- 禁止迁移命令使用无条件 `|| true`。
- 构建、迁移、依赖健康、认证 smoke 任一失败都阻止流量切换。
- 健康检查包含 PostgreSQL、Redis、队列最老任务、worker/GPU 心跳和供应商关键通道。
- 发布保留上一版本前后端和迁移兼容窗口。

**验收**：模拟迁移失败、构建失败和健康失败，部署均中止；线上可查询当前 Git SHA、前端构建 SHA 和迁移版本。

**当前状态**：第三阶段完成，待远端部署核验。自动部署与线上部署统一使用 migration ledger 执行器，记录迁移路径、SHA-256 校验和、执行时间和 Git SHA；通过 PostgreSQL advisory lock 串行化迁移，已执行版本跳过，内容变更或执行失败强制中止。`/health` 已加入 PostgreSQL、迁移账本、发布元数据、Redis/数据库队列数量、最老排队/执行任务年龄及卡死/不一致判定，并纳入已配置 GPU Agent 可用性和已启用关键供应商的缓存健康状态；供应商检查不触发真实生成和计费。正式部署默认强制执行当前版本 smoke，健康、迁移、认证或核心只读流程任一失败即回滚；仅在架构契约和 smoke 通过后激活 Git SHA、前后端源码 SHA-256 与发布时间。

## 5. P1：主流程完整性

### SCRIPT-001 剧本候选、主剧本与编辑体验

- 文件列表用于保存候选剧本；每个候选的改写、分段、视频脚本和分镜草稿独立。
- 主编辑区默认只显示文件列表、对话式编辑和可折叠资产侧栏；四栏总览作为高级模式。
- “设为主剧本”使用整行按钮并显示后续影响；失败提示区分权限、保存冲突、网络和数据无效。
- 视频反推作为剧本工具，输出直接创建带来源、费用和版本信息的候选剧本。

### STORY-001 分镜生成、验收和迭代

- 重生成不直接追加活动镜头，先生成候选版本并显示差异。
- 支持基于用户反馈继续修改，不要求每次从零生成。
- 角色一致性、脚本符合度、场景一致性、道具一致性、多余人物和视觉质量作为验收指标。
- 自动重试默认最多一次；继续重试显示预计费用并由用户确认。
- 质量服务不可用时标记“未验证”，不得伪装为通过；是否进入活动链路由产品策略明确控制。

### MODEL-001 数据驱动模型能力清单

- 建立统一 `ModelCapabilityManifest`，声明文本、图像、视频、语音和 GPU 能力。
- 图像模型声明参考图数量、参考职责、比例、尺寸、编辑和验收策略。
- 视频模型声明输入类型、首尾帧、多图、参考音、可选时长、分辨率耦合、原声、取消和查询。
- GPU 工作流声明版本、模型依赖、输入输出、显存、分辨率和兼容节点。
- 前台只展示有效参数组合；任何降级必须在提交前说明，不得静默把 1080P 改为 720P 或把时长归一。
- 跨按量/Plan 回退仅在目标通道完整覆盖当前请求能力时自动执行。

**当前状态**：第一阶段完成。`/api/video/capabilities` 已返回版本化、无密钥的能力清单，首批覆盖 Seedance、MiniMax 和 ComfyUI/GPU；旧布尔字段继续兼容，前端以单次缓存请求共享能力结果。MiniMax Hailuo 2.3 / Fast 已补齐模型、时长、分辨率和提示词优化参数；`1080P + 10 秒` 等非法组合由前台禁用并在提交前、后端入队前双重拒绝，不再静默改成 6 秒。DashScope 等其余供应商及管理后台编辑能力仍待接入。

### VIDEO-001 视频工作区差异同步和 take

- 首次导入后持久化工作区，不再每次进入要求重新导入。
- 再次导入先显示新增、更新、归档和参数影响；默认差异同步。
- 全量覆盖需要确认并创建恢复点，不能自动删除任务、参数和已生成视频。
- 每个镜头保存多个 take，并持久化 `selected_take_id`。
- 裁剪、末帧续写、原声和角色音色参考均记录来源和版本。

### AUDIO-001 参考配音、角色音色和最终音轨

- 配音定位为镜头时长和视频生成参考，不默认包装为最终对白。
- 实际音频时长反向更新镜头时长和时间轴。
- 视频音频优先级：手工指定 > 角色视频音色基准 > 分镜参考配音 > 模型自由生成。
- 静音视频允许采用参考配音作为候选音轨。
- 美化阶段支持视频原声、参考配音、配音演员上传和 GPU 对嘴。

### FINAL-001 成品版本和发布

- 每个成品保存活动分镜版本、镜头顺序、所选 take、音轨模式、编辑版本和生成时间。
- 首页展示明确发布版本，而不是按标题或数组第一条猜测。
- 历史版本可浏览、比较、复制和重新编辑，但不默认进入当前发布链路。

### ADMIN-001 API 卡片和请求级路由

- 一个 API Key 对应一张卡片；一张卡可绑定多个前台操作和模型。
- 同一供应商允许多张 Key 卡；同一个模型绑定只启用一个 Key，避免歧义。
- 国内站、国际站、按量和 Plan 是卡片属性，运行时按操作解析具体 `config_id`。
- 停止把卡片投影为进程级环境变量；凭证、模型绑定和操作能力拆分存储。
- Key 必须加密保存；缺少加密密钥时禁止新增，而不是退化为 Base64。
- 真实生成测试默认不执行视频等高费用操作；明确显示可能费用并要求确认。

## 6. P2：体验和运营

### UX-001 统一反馈和危险操作

- 替换浏览器 `alert/confirm` 为产品内 toast、行内错误和标准确认弹窗。
- 批量任务进入任务中心，保留每项状态，支持“仅重试失败项”。
- 错误详情可展开，展示模型、通道、Request ID、时间和建议动作。

### GPU-001 工作流能力与节点调度

- 角度调整、高清放大、去水印、补帧、对嘴等所有 GPU 工具统一使用节点选择器。
- 选择器显示在线、繁忙、排队、兼容工作流和用户覆盖选择。
- 不兼容节点不可选；任务记录实际节点、工作流版本、输入哈希和处理耗时。

### OPS-001 用量、余额和告警

- 供应商余额、套餐余量、重置时间和到期时间定时同步。
- 支持阈值告警、失败率告警和预计耗尽时间。
- 调用日志串联 `request_id/task_id/provider_request_id/user/project/episode/model/config_id/duration/credit_delta`。

## 7. 数据迁移策略

1. 先只读扫描：主剧本冲突、跨集 `script_id`、重复分镜、孤儿资产、无效绑定、多条活动冻结、零分账户和运行中任务。
2. 新字段和新表先上线，旧字段保持读取兼容。
3. 双写主剧本、绑定、任务和积分状态；通过对账任务持续比较新旧结果。
4. 冲突数据进入人工处理队列，不按同名自动合并人物、场景或道具。
5. 运行中任务在旧状态机自然收敛后再关闭旧读路径。
6. 停止旧读前执行全量回归和线上只读审计。

## 8. 上线门槛

- 对象权限负向测试无越权、无对象存在性泄露。
- 分镜重生成、切换主剧本和视频再导入不造成无标识追加或数据丢失。
- 锁定角色、场景、道具与供应商请求快照完全一致。
- 长任务刷新、断网、断 SSE、worker/API 重启后状态能够恢复。
- 积分并发、重复回调、取消与完成竞争测试满足守恒和幂等。
- 所有模型无静默参数降级；能力不匹配在提交前阻止。
- 正式部署强制迁移、远程 smoke 和依赖健康检查。
